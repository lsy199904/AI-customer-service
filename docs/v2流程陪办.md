# v2：问题澄清与业务流程陪办

本分支基于当前main，保留真实文字流式、知识图片、来源、身份隔离和按月会话日志。主知识源仍为 `knowledge_sources/SmartTITU客户问答.docx`，其内容对应《SmartTITU外部客户知识库_20261026_v5_业务全流程版.docx》，不新增过时FAQ，不改写原文档和图片。

## 本版功能

- 普通问题照常检索、重排并流式回答，不强制进入流程。
- “支付不了”等模糊输入先区分账单支付和充值；“认证失败”区分企业认证和API密钥场景；没有当前任务的“下一步”会先询问流程。“第一个”等可以接着上一轮澄清选项选择。这是有限规则覆盖，不是任意模糊问题的通用推理保证。
- 六个流程：注册、企业认证、服务订购、客户充值、账单支付、在线开票。章节回答末尾提供“带我一步步办理”，也可直接输入“分步指导：企业认证流程”。
- 进入后显示阶段卡，支持“这一步已完成”“这一步怎么做”“返回上一步”“结束指导”，也支持输入“下一步”“上一步”“重新开始”。不因普通追问擅自推进，“好的”“谢谢”等简短确认保留当前步骤而不推进。
- 每个阶段说明取自当前活动知识的对应编号条目，由模型围绕当前阶段解释；未配置回答模型的extractive模式直接展示当前阶段原文。流程配置只定义阶段标题及对应条目号，不复制业务答案。
- 流程图和手册在陪办消息中折叠展示，随时可展开。旧消息中的操作按钮失效，避免误点旧步骤。
- 阶段走完提供关联流程入口，例如注册→企业认证。它只是可选问题，不表示用户必须办理。

## 状态与边界

`guidance` 是服务端输出元数据，包括 flow_id、title、step（从0开始）、total、stages、status（active/completed/ended）、source_revision、note，可包含知识更新notice。actions新增guide/clarify类型，含label/message；点击仍提交普通message与request_id，不允许客户端上传步骤状态。

状态随已有消息写入数据库，支持服务重启后恢复同一会话，不需要新增表或迁移。不同企业、用户、会话沿用现有隔离。相同请求编号重试不推进两次。空闲超过现有SESSION_IDLE_SECONDS或切换话题后，不再沿用旧任务；历史记录仍保留。操作异常未保存时，不算完成本次推进。

只有当前活动知识具备完整编号步骤，才提供对应陪办。后续编辑文档重排编号时需同步检查 app/assistance.py 的阶段映射。知识修订变更时重置到第一阶段，停用或检索不到章节时不沿用旧答案；不降低向量或重排门槛。

所有进度都是用户自述，未查询后台，也不会执行充值、支付、开票、认证、工单提交。流程完成只表示指引结束，不表示业务办理成功。真实业务问题仍提示接口未接入。文字仍由提示词约束，没有重新加入模型JSON校验或格式重试。

## 切换服务器到v2

工作目录有本地修改时先查看git status，不要使用reset覆盖部署配置。

```bash
cd ~/ai_customer
git fetch origin v2 &&
git switch v2 &&
git pull --ff-only origin v2 &&
sh scripts/enterprise.sh start
```

浏览器强制刷新。已经导入最新版知识库时无需重新ingest、重建镜像或迁移数据库；首次使用其他知识库时，需正常导入对应最新版文档才会出现六个指导入口。main分支没有这些新功能，切回main并重新创建assistant即可恢复原问答界面；新功能的历史元数据对旧版本不构成必需字段。

## 手工验收

1. 输入“支付不了”→看到两种场景；输入“第一个”→按账单支付流程回答。
2. 输入“企业认证流程”→普通介绍及“带我一步步办理”。
3. 点击指导入口→第1/4阶段；提问“这一步怎么做”→仍在第1阶段。
4. 点击“这一步已完成”→第2阶段；“返回上一步”→第1阶段。
5. 刷新或重启服务→同一会话历史保留；下一次阶段问题继续正确进度。
6. 新建会话并输入“下一步”→重新选择流程，不继承其他会话任务。
7. 换问“在线开票流程”或“模型有哪些”→正常新主题，不沿用企业认证。
8. 输入“我的余额是多少”→明确未接业务接口；输入“转人工”→显示人工入口。

日志增加 assistance_planned、clarification_requested、guidance_step_selected、guidance_closed 等事件，仍归入每次问答的一个JSON，使用同一请求编号排查。bootstrap返回version=v2，capabilities包含guidance/clarification。

## 分享给其他人测试

```bash
cd ~/ai_customer/ai_customer_v2
git pull --ff-only origin v2 &&
python3 scripts/configure_demo_access.py enable &&
sh scripts/enterprise.sh start
```

分享 `http://服务器IP:8100/widget/demo`。如果v2配置了其他端口，以实际PORT为准。浏览器强制刷新后无需手填凭证；不同浏览器使用隔离的临时测试身份。同一浏览器的多标签页共享身份。此功能默认关闭，正式平台iframe身份对接保持原样。测试结束执行 `python3 scripts/configure_demo_access.py disable && sh scripts/enterprise.sh start`。开关改变后必须重新创建容器，仅docker restart不会加载新环境变量。
