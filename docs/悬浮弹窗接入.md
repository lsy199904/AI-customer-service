# iframe 客服接入

客服现提供独立聊天地址 `/chatbot`。聊天窗口、问答、图片、来源和历史会话由客服服务提供，业务前端只需嵌入。实现采用标准 iframe，与 Dify 的嵌入形式相同；使用本项目自己的后端，不需要安装 Dify。

## 配置与部署

在客服 `.env` 增加父页面的准确来源，然后重启服务：

```dotenv
FRAME_ORIGINS=https://console.example.com
```

多个来源用逗号分隔，不带路径或末尾斜杠。例如开发环境可加入 `http://localhost:3000`。默认仅允许客服服务同源页面嵌入，禁止通配符。`FRAME_ORIGINS` 控制哪些站点可放 iframe，`CORS_ORIGINS` 控制外部页面直接调用 API，两者用途不同。iframe 内 API 调用同源，无需为此额外添加 CORS。反向代理不要对 `/chatbot` 加 `X-Frame-Options: DENY/SAMEORIGIN`，也不要用其他 CSP 覆盖本服务的 `frame-ancestors`；主站 CSP 的 `frame-src` 须允许客服域名。

默认容器只在宿主机回环地址监听。生产环境先配置 HTTPS 反向代理，再把 `https://assistant.example.com/chatbot` 交给前端；其他电脑不能使用你的 `127.0.0.1` 地址。

## 悬浮 iframe 推荐方式

在现有企业页面加入下面的脚本，由脚本自动创建右下角入口与 iframe：

```html
<script src="https://assistant.example.com/iframe.js"
        data-auth-url="/api/assistant/token" defer></script>
```

脚本从业务页面同源的 `/api/assistant/token` 读取当前登录人的短期凭证，通过限定来源的 `postMessage` 交给 iframe。凭证不放 URL、页面缓存或 localStorage。父页每次收到凭证请求都会重新取凭证，可适应到期刷新。接口必须根据服务端现有登录态识别企业和用户，返回 `{"token":"短期签名凭证"}`，设置 `Cache-Control: no-store`；未登录返回401。签名可在可信后端使用 `app.core.issue_token`，`AUTH_SECRET` 只保存在可信后端。不能让浏览器任意指定企业或用户。当前仓库没有你们登录系统代码，该接口需要业务后端完成适配。

退出登录或切换账户时调用：

```js
window.SmartTITUEmbed.reset();
```

可调用 `open()`、`close()`、`reset()` 和 `destroy()`。历史与会话继续由后端按照企业和用户隔离，切换账号必须重置；旧请求的凭证结果会被丢弃。

## 直接嵌入 iframe

需要常驻布局时，业务前端可以直接放：

```html
<iframe id="customer-service" title="SmartTITU 智能客服"
  src="https://assistant.example.com/chatbot?parent_origin=https%3A%2F%2Fconsole.example.com"
  style="width:100%;height:680px;border:0" referrerpolicy="no-referrer"></iframe>
```

`parent_origin` 必须等于实际父页面的 `location.origin`，且列入 `FRAME_ORIGINS`。它不是凭证。有企业身份隔离时，不能仅靠一个公开地址识别用户；父页面还须完成下面的身份桥接：

```js
const chat = document.getElementById('customer-service');
const assistantOrigin = 'https://assistant.example.com';
let identityVersion = 0;
window.addEventListener('message', async event => {
  if (event.origin !== assistantOrigin || event.source !== chat.contentWindow) return;
  if (event.data?.type !== 'smarttitu:token-request') return;
  const version = identityVersion;
  try {
    const response = await fetch('/api/assistant/token', {credentials: 'same-origin', cache: 'no-store'});
    if (!response.ok) throw new Error('请先登录');
    const payload = await response.json();
    if (version !== identityVersion) return;
    chat.contentWindow.postMessage({type: 'smarttitu:token-response', id: event.data.id, token: payload.token}, assistantOrigin);
  } catch {
    if (version === identityVersion) chat.contentWindow.postMessage({type: 'smarttitu:token-response', id: event.data.id, error: 'unauthorized'}, assistantOrigin);
  }
});
function resetCustomerService() {
  identityVersion++;
  chat.contentWindow.postMessage({type: 'smarttitu:reset'}, assistantOrigin);
}
```

在退出或切换账号前调用 `resetCustomerService()`，重新登录后发送 `smarttitu:open`。双方都校验消息来源和窗口，不使用 `postMessage(..., '*')`。收起按钮会向父页面发送 `smarttitu:close`，常驻布局可忽略该消息。

## 连接等待或 Failed to fetch

客户端初始化请求现在设15秒超时，问答请求设120秒超时；超时后显示提示与重试入口。演示页仅在初始化完成后显示已连接，失败后可以直接重试。初始化提示区分加载会话及恢复历史阶段，错误不会再无限停在加载状态。

浏览器所在电脑与服务主机不同的时候，浏览器127.0.0.1指向自己的电脑。服务默认只监听服务器回环地址，需要建立SSH隧道。可在自己电脑终端执行（主机名替换为平时SSH使用的地址）：

```bash
ssh -o ExitOnForwardFailure=yes -N -L 18000:127.0.0.1:8000 sylvanli@cnglus065
```

保持连接，先在浏览器打开 `http://127.0.0.1:18000/health`，应看到 `{"status":"ok"}`；再打开 `http://127.0.0.1:18000/chatbot` 或 `/widget/demo`。健康检查也打不开时先检查隧道、端口与代理；健康检查能打开而聊天请求失败时，再核对浏览器Network中的失败接口状态（不共享Authorization或token）。登录过期通常会返回明确401，Failed to fetch本身不能证明是凭证失效。
