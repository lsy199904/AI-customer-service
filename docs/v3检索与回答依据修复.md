# v3 检索与回答依据修复

本次修改针对“安装MetalLB负载均衡器”被验证、排错、部署准备章节挤掉，以及旧助手回答中的命令被再次采用的问题。

## 候选选择

- 仅在标题比较时去掉“问题编号”“页码”“附录-”等结构前缀，并处理问句礼貌用语。显示标题、正文、Embedding输入和索引版本保持不变。
- 明确指向唯一章节时，在重排过滤前保留该章节的候选。允许其重排分数低于门槛，并在日志标记 `selected_primary_title`、`rerank_gate_bypassed`。不再补齐其他主题到三条。
- 同标题出现在不同活动文档时，不随意指定主章节。非明确标题问法继续走向量/BM25混合召回、重排门槛和上下文数量限制；未降低全局阈值。
- 推荐问题增加服务端生成的 `suggestion_sources` 映射，保留原字符串列表兼容界面。点击时复查活动知识ID、标题与修订；已停用/旧修订不能被推荐恢复。

## 回答依据与引用

知识问答仍保存原有会话，检索追问和陪办流程仍使用历史。知识生成提示不再包含历史问答正文，改用本轮解析后的问题、当前证据及当前陪办阶段；闲聊保持原有流式行为。

来源不再无条件附上全部候选，改为按回答段落的词项支持选择来源。命令、代码块行、版本、URL、IPv4/地址池增加本轮引用证据的字面校验；陪办仅以当前阶段材料校验。最终校验不通过时不附引用/图片，返回现有推荐和转人工入口，并排除当前失败问题，避免重复推荐。

知识回答与问候均在模型生成时直接发送 delta，可取消；最终完成时再校验依据，浏览器以 complete 的正式答案替换流式草稿。校验不通过时，已流出的草稿可能短暂可见，但不会保存在最终答案或历史中。字面与词项校验不能证明所有自然语言事实正确，真实模型问法和文档覆盖率仍需独立评测。

## 排查日志

普通请求日志新增 `retrieval_candidates`：候选知识ID/标题、召回通道、向量分数、BM25、RRF、重排分数和门槛、标题匹配类型、是否入选与原因。最高向量分数通过 `similarity_knowledge_id` 关联知识。原文与模型输入仍由 `LOG_DEBUG_CONTENT` 控制。候选明细及调试对象不进入客户的 `retrieval` 字段。

## 更新服务器

在正在提供 v3 服务的目录执行，保留现有 `.env`、Word、模型和数据库：

```sh
cd ~/ai_customer/ai_customer_v3
git pull --ff-only origin v3 &&
sh scripts/v3.sh start &&
sh scripts/v3.sh doctor
```

无需重新入库或重建向量，无新增依赖。`start` 强制重新创建 assistant 容器以加载 `.env`，保留现有 Compose 项目名和 `V3_PORT`。不启动其他基础服务、不主动拉镜像。

`retrieval` 不传参数时保留阈值；仅显式参数才修改，例如：

```sh
sh scripts/v3.sh retrieval --semantic 0.75 --rerank 0.60
sh scripts/v3.sh start
```
