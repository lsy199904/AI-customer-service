## PDF通用图片清洗

图片分析在入库阶段执行，不增加问答完成后的串行模型调用。PDFium读取位图、位置及邻近正文；本地RapidOCR识别文字，zxing解码二维码，不访问二维码指向的网站。CPU模型随依赖包提供，不需要额外模型服务。

仅明确识别的图示、证书、信息图和用途明确的二维码登记为可展示资源。装饰、视频封面及往期推荐排除；用途不明、绑定有歧义或提取失败的图片记录为待核对，不强行展示。纯矢量图或扫描页不保证自动识别，报告中留待核对。文字PDF原有主题切分保持。

普通业务问题不会因来源含二维码而附二维码。试用申请、访问官网、关注及联系二维码分用途处理；只有本轮明确请求对应入口且当前证据有关联时才展示。试用二维码不会替代人工客服企业微信码。没有可展示二维码时，生成证据移除扫码提示，避免指引客户扫描未返回的图。

生成图片采用稳定资源标识与去重，保留旧资源供历史会话使用。`var/pdf_media/`含缓存、资源与核对报告，不提交Git。仅已登记且明确保留的资源可通过服务访问；不明确图片不能直接访问。不要清空此目录，否则历史图片可能失效。

`sh scripts/v3.sh media-report`查看状态及排除原因，`--full`查看OCR和二维码内容（仅供运维核对）。调整核对报告后需重新入库，使关联结果更新。

针对原文明确列举的核心价值等清单，检索复用现有标题选择机制识别原文清单名称及数量，优先保留直接证据；不硬编码产品答案，不调整相似度或重排门槛。

## 部署

本次新增本地图片处理依赖及系统运行库，需要构建镜像。PDF解析版本和Word内容版本都会触发增量更新，无需清空知识库或执行全量重建。

```sh
cd ~/ai_customer/ai_customer_v3
git pull --ff-only origin v3 &&
sh scripts/v3.sh upgrade &&
sh scripts/v3.sh doctor
```

`upgrade`先构建镜像，再用新镜像执行一次性入库，成功后重建服务容器并检查。构建或入库失败会停止后续步骤，保留原服务。首次处理图片会比纯文字入库耗时更长。现有模型目录、数据库、Milvus及配置不迁移。网络需要能获取新增镜像构建依赖。

开发环境验证包含真实PDF提取与二维码解码、PNG访问、流式正文、最终引用/图片与历史一致性，以及文档中心29篇文章覆盖检查；不等于生产Qwen/Milvus端到端验收。部署后需要使用实际账号验收问答、流式与配图。
