# 正式环境链接与迁移

## 客户可见链接

CUSTOMER_LINK_HOSTS配置可跳转的准确官网域名，默认www.smarttitu.cn、smarttitu.cn、console.smarttitu.cn、doc.smarttitu.cn。只允许HTTPS、默认端口和无用户名密码的地址，不因前缀相似而接受其他域名。新增正式文档域名时改此配置并重建服务容器；不将飞书、GitHub或临时网关加入白名单。

正文的飞书、GitHub等Markdown链接保留名称、移除地址；非白名单裸链接移除。接口地址api.smarttitu.cn在技术说明中保留，但不自动变成跳转链接。命令、配置或示例放在代码块中保留原文字面值，不由本次更新改写业务参数。资料原始来源仍存数据库及Word用于后台追溯；不需要删除Word来源。

后端在生成证据、流式增量、最终API、历史读取、重复请求及来源详情执行同一规则。流式只暂存未完成的链接，不缓存整段答案，不等待生成后审查。前端按bootstrap下发的域名规则渲染，代码块及行内代码不生成超链接。引用仍打开站内来源摘要，不跳飞书等外部文件。

图片只返回/media/下的本地资源：app/static/media为原有图片，var/pdf_media含提取的图片、登记报告及缓存。前端相对客服服务的apiBase加载资源，而非相对宿主网站路径。既有外部图片地址不会继续返回；新增图片先登记本地资源，不使用GitHub外链。

## 更新当前服务器

```sh
cd ~/ai_customer/ai_customer_v3
git pull --ff-only origin v3 &&
sh scripts/v3.sh upgrade &&
sh scripts/v3.sh doctor
```

本次链接展示规则不需要修改Word或清空数据库。upgrade沿用统一构建、增量入库及重建容器步骤；如果上次文档中心Word或PDF图片尚未入库，也会更新。正式域名需HTTPS反向代理，将API与/media/请求转发到同一客服服务，流式路由关闭代理缓冲。身份认证、跨域和iframe权限沿用现有接入配置，本次不更改。

## 只打包知识和图片

```sh
sh scripts/v3.sh bundle --output backups/knowledge-media.tar.gz
```

迁移包包括knowledge_sources、data/media.json、app/static/media、var/pdf_media，含每个文件的SHA256和打包时的代码提交号（有Git时）。不会包含.env、模型权重、日志或聊天数据库。PDF_MEDIA_DIR或MEDIA_PATH使用非标准目录时会停止并提示，避免漏拷。配置文件需要在新主机单独配置，不能只搬这个包就声称数据库已经迁移。

## PostgreSQL加Milvus现有部署的完整数据迁移

在旧主机安排维护窗口，停止接入新请求、等待当前请求结束，再运行：

```sh
sh scripts/v3.sh migration-export
```

该命令临时停止assistant，调用现有export-storage将聊天和知识版本导出为便携SQLite快照，再与知识、图片打成backups/migration-时间/knowledge-and-history.tar.gz，退出时恢复旧assistant。导出仅适用于当前PostgreSQL模式，不迁移在途工作流检查点，不停止数据库或其他服务。

在新主机使用相同代码版本，准备独立的空PostgreSQL与Milvus并配置.env，模型地址可以指向已有模型服务。模型地址、数据库地址及MODEL_HTTP_ORIGINS须按新环境填写；迁移包不带模型或密钥。将迁移包放在项目下，再运行：

```sh
sh scripts/v3.sh restore-bundle --archive /实际存放位置/knowledge-and-history.tar.gz
sh scripts/v3.sh build
# 数据库及Milvus应已启动；此时不要让assistant接收用户请求。
# 以下沿用现有离线导入与向量同步功能：
```

使用与v3.sh相同的Compose配置运行一次性容器（主机当前用户）：

```sh
export ASSISTANT_UID=$(id -u) ASSISTANT_GID=$(id -g)
docker compose -f compose.v3.yaml run --rm --no-deps -T assistant \
  python manage.py migrate-storage \
  --chat /ai_customer/migration-storage/assistant.db \
  --knowledge /ai_customer/migration-storage/rag.sqlite3
docker compose -f compose.v3.yaml run --rm --no-deps -T assistant python manage.py sync-vectors
sh scripts/v3.sh start
sh scripts/v3.sh check
sh scripts/v3.sh doctor
```

migrate-storage要求目标数据库没有已有聊天/知识，不覆盖现有数据。sync-vectors使用迁移的已有向量同步Milvus，不重新调用Embedding。恢复程序先核对所有文件哈希及路径，拒绝路径穿越、符号链接和不同内容覆盖；应使用与迁移时相同提交的干净项目目录。重复恢复相同文件不会重复写入。

验收流式问答、旧会话、站内来源、图片预览与放大后，再将正式入口切到新主机。迁移回归覆盖本地资源及数据库导出文件的打包恢复；本地没有生产Docker、PostgreSQL/Milvus环境，真实跨主机切换仍需在服务器维护窗口验收。
