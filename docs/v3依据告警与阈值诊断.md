# v3 依据告警与阈值诊断

## 根因与修复

原 `SupportWorkflow.generate` 在模型完成后检查字面依据，发现未支持的命令、版本、URL、地址或配置行时，返回 `unsupported_answer`。后续验证节点将整个答案改为兜底并清空来源；因此检索成功、模型成功也可能最终显示无法回答。

现已移除这条阻断路径。文字增量持续直接发送，检查及检查本身的异常只记录后台告警，不修改正文、引用、成功状态或历史。正式完成事件保存成功生成的同一正文。模型超时/接口错误、检索失败、完全未命中、模型明确认为证据不足等原有处理保留。

系统提示加强：只基于本轮证据写已有步骤；缺少命令、配置或环境参数时说明缺口，不自编示例地址池、IP、YAML或命令，不因为局部缺少细节就拒答已知部分。知识生成不读取历史助手答案正文。提示词无法保证模型绝不补写，告警用于识别具体问题，而不是掩盖已生成的回答。

## 标题简称

原先“安装MetalLB”和“安装MetalLB负载均衡器”不相等，未触发主标题保护。新增有界的“操作动词+英文产品标识+可省略的通用角色名”比较，支持“如何安装MetalLB”“MetalLB怎么安装”等；安装、配置、升级等操作不同不混同，故障排查、前置条件和其他产品不强行当作安装章节。同标题/简称指向多个活动章节时，不随意指定唯一主知识。

混合召回、重排算法、阈值和上下文数量没有改变；明确唯一标题仍沿用既有主知识保留机制。Embedding输入和索引指纹未改，无需重新入库。知识库业务正文、配图规则及认证隔离均未修改。

## 告警与失败日志

- `generation_grounding_warning`：WARNING级别，仅告警。包含具体`text`、`answer_excerpt`、知识ID、检查范围、判定原因；对应证据的ID、标题、修订和正文只存一份。陪办还记录当前阶段证据。已知配置密钥、Bearer等会脱敏。
- 具体依据告警按本次产品要求写入每请求运维日志，即使未启用全文debug也可排查；常规模型输入/输出全文仍由`LOG_DEBUG_CONTENT`控制。
- `generation_grounding_check_unavailable`：检查本身不可用，不影响成功回答。
- `retrieval_failed`/`retrieval_timeout`：检索故障；`model_request_failed`/`generation_failed`：模型故障；`stream_failed`：流式发送故障。依据告警不计作请求失败节点。

## 重排门槛来源

当前代码默认 `RERANK_MIN_SCORE=0.6`，`.env.example`也为0.6；`compose.v3.yaml`未写死该值。`v3.sh retrieval`不传参数不修改配置，仅显式`--rerank`才写`.env`。

实际使用的是进程环境值；Docker Compose在创建容器时读取`env_file: .env`。运行中修改宿主机.env不会改变旧容器环境。`manage.py`读取.env使用setdefault，因此也不会覆盖已存在的进程环境。日志中0.0表示当时生效配置确为0.0，不能据此认定代码默认是0，也不能在未读取服务器环境时断言是谁修改的。

新增只读诊断：

```sh
cd ~/ai_customer/ai_customer_v3
sh scripts/v3.sh config
```

逐项输出实际阈值、进程环境/代码默认/显式设置来源、.env对应行和值、是否重复、文件与实际值是否相同。不输出其他配置或密钥，不连接模型、不修改配置。文件0.6但进程0.0时，应排查旧容器或启动环境覆盖；两处都0.0时，当前配置文件就提供了0.0。检索候选日志也记录本次实际阈值和来源。

本次不设置或恢复任何门槛，不执行`retrieval --rerank`，避免修改用户测试条件。

## 验证与部署

Python 3.12和锁定依赖下285项测试：277项通过，8项因私有文档/真实PostgreSQL环境未配置而跳过。覆盖向量0.7062、重排0.3733、实际门槛0.0的案例，以及0.6下唯一标题保护；合理简称和不应匹配的负例；真实HTTP首段早于生成结束；已有步骤无示例IP输出；告警不替换正文、不清空引用，历史与最终完成事件一致；检查器异常、模型超时与未命中保持原有处理。

模型输出用受控替身验证，未连接生产Qwen做生成质量评测，不能保证提示词完全消除补写。未修改服务器.env，也未实际部署服务器容器。

```sh
cd ~/ai_customer/ai_customer_v3
git pull --ff-only origin v3 &&
sh scripts/v3.sh config &&
sh scripts/v3.sh start &&
sh scripts/v3.sh doctor
```

挂载部署只需重新创建assistant容器，无新依赖，不用重新构建镜像或重新入库。`config`放在重新创建前，可保留旧容器实际值与新文件的对比；必要时启动后再执行一次作比较。
