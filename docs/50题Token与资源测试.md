# 50题Token与资源测试

复用原 `scripts/model_benchmark.py` 的采样、独立会话和报告机制。默认五题入口不变，新增一键50题入口。

## 问题处理

用户原清单从3到53共51题。原31和39是同一个“数据不出域，适合哪种服务”问题，保留一题后共50题。原25补全为29号提交星级权益调整的独立问法；超时时间、信通院评估依据、API Base URL等补全平台语境。其余虽有主题交叉，但问题侧重点不同，不再合并。

## 服务器运行

模型容器就绪、4001网关可用且 `sh scripts/v3.sh doctor` 通过后：

```bash
cd ~/ai_customer/ai_customer_v3
sh scripts/model-benchmark-50.sh
```

默认GPU标签，BGE容器 `model-serving-bge-m3-1`、重排容器 `qwen3-reranker-4b`。实际GPU模式仍需核对容器镜像、设备与进程，脚本标签不会切换模型设备。名字不同时：

```bash
sh scripts/model-benchmark-50.sh \
  --embedding-container 实际BGE容器名 \
  --rerank-container 实际重排容器名
```

仅修改测试脚本，不需重建客服镜像、重新入库或修改运行中的问答逻辑。串行50次真实提问，各建独立会话，可能增加共享模型负载；不要与演示、其他压测同时运行。请求开始默认最少间隔3.1秒，完成后再冷却3秒，适配每分钟20问；其他相同租户流量仍可能占用额度。实际总时长取决于模型和超时，50题可能约10至30分钟或更久，不是并发测试。

## 有效样本判定

必须实际记录到 `stage=llm, purpose=answer, status=completed`，并且问答状态是 `answered`、正文非空，才计为完成LLM正文生成。仅调用图片判断或证据选择模型不算。固定回复、转人工、澄清、未命中和模型失败不伪装成LLM样本。

`--require-answer-llm` 默认由50题入口启用；如果某题未完成LLM正文生成，仍继续测其余题并保存结果，最终以非零状态退出。不会修改服务路由以强制生成，也不保证知识库可回答全部50题。需根据实际报告确认有效题数。

Token报告分别列示“正文有效样本的已记录量”与“全部调用usage完整的子集”。辅助模型调用也计入每问总量；未知usage不按0补齐，不将缺失调用当完整总成本。正文生成成功不等于业务事实正确，仍应抽检答案。

## 输出

新建 `var/model-benchmarks/gpu-时间-编号/`，不覆盖旧报告。

- `报告.md`：逐题结果、实际LLM正文生成核验、Token汇总及资源。
- `results.json`：逐题正文、所有阶段调用、usage、资源、有效性和汇总。
- `tokens.csv`：每题输入、输出、总Token、LLM调用次数、usage完整性与正文生成标记。
- `resources.csv`：资源采样与候选数量。
- `samples.jsonl`：原始采样。

原五题对照仍可用原命令；50题不要直接拿五题旧报告当同规模对比。保留原报告，比较时只选双方都完成且配置可比的问题。
