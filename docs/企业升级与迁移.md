# 企业版升级与迁移

本次增加 LangChain + LangGraph、PostgreSQL、Milvus 和 SSE。继续使用已运行的 BGE-M3、Qwen3-Reranker-4B、Qwen3-32B；不另起 GPU 模型，不改动 models/。这是一套可部署的单机企业客服基础设施，不等同于多机高可用集群。

## 现有 Linux 主机升级

适用于现有 ~/ai_customer，使用宿主机网络连接模型的部署。先确认 Git 工作区没有需要合并的本地代码修改；不要删除 models、var、knowledge_sources、.env。Word/PDF 不随代码更新上传，保留你已经上传并入库的版本。镜像不携带来源 Word/PDF，实际资料以挂载的私有来源目录和迁移后的知识数据库为准。

先在旧镜像内备份，再拉取代码，避免挂载的新代码需要尚未安装的依赖：

```bash
cd ~/ai_customer
sh scripts/docker-host.sh exec assistant python manage.py backup &&
git pull --ff-only origin main
```

如果已经拉取新代码，旧镜像提示缺少依赖，不要重新启动旧镜像；继续构建新企业镜像。迁移步骤自身会在停止旧服务后备份两个 SQLite（包含 WAL 内容）。另外保管 .env、knowledge_sources/、data/media.json、app/static/media/；备份是私密资料，不推 Git。

```bash
sh scripts/enterprise.sh configure &&
sh scripts/enterprise.sh build &&
sh scripts/enterprise.sh infrastructure
```

configure 保留 AUTH_SECRET、模型地址/密钥及监听地址，备份原 .env，然后生成 PostgreSQL、MinIO、Milvus 和运维凭证；不会把密钥打印到终端。新配置保存在本机 .env，Milvus 配置在 deploy/generated/milvus-user.yaml，二者不入 Git。此时仅启动数据库基础设施，旧客服进程仍继续运行。依赖需要构建镜像，restart 不会安装依赖。

基础设施额外需要 CPU、磁盘和内存，建议先预留约 6GB 可用内存及充足磁盘作为起点，实际以本机模型和压测为准。数据库和 Milvus 不占 GPU；不要挤占模型服务内存。PostgreSQL应用使用非超级用户角色，具备本库建表所需权限，管理账号只用于初始化和备份；初始化脚本仅在新卷执行。PostgreSQL 使用回环端口 55432、Milvus 使用回环端口 19530；如被其他服务占用，先调整配置及 Compose 对应端口，不能直接复用别人的数据库。etcd、MinIO、Milvus 的管理端口不向宿主机开放。

在维护窗口执行以下步骤，迁移期间暂停新会话请求：

```bash
sh scripts/enterprise.sh migrate &&
sh scripts/enterprise.sh start &&
sh scripts/enterprise.sh doctor
```

migrate 会停止旧客服，使用 SQLite backup API 保存一致性副本，事务性迁移会话、消息顺序、文档原始快照、版本、历史引用和已有向量，再将向量同步到 Milvus；不重复调用 Embedding。迁移冲突会回滚，原 SQLite 不删除，失败后服务保持停止供排查。首次升级针对旧会话和知识；不同数据库之间的未完成 LangGraph 检查点不能直接搬迁，维护前须让在途请求完成。

start 后 doctor 实际检查关系库、持久化检查点、活动知识数、Milvus 检索以及三个模型的接口。它不代表业务准确率已经通过验收。预期框架显示 langchain、langgraph；database=postgresql、vector_backend=milvus。知识数量应与你当前私有 Word 入库结果一致，当前整理版为 50 个主题；迁移不会擅自把旧索引更新成新 Word，若旧索引还是 71/142，需按下节先整理活动来源并入库。

```bash
sh scripts/enterprise.sh exec assistant python manage.py check
sh scripts/enterprise.sh exec assistant python manage.py documents
sh scripts/enterprise.sh exec assistant python manage.py token --tenant demo --user tester
curl --max-time 10 http://127.0.0.1:8000/ready
```

浏览器强制刷新页面以加载新版脚本。公司内网直连需在 .env 设置 HOST=0.0.0.0，再 enterprise.sh start；获准网络可访问 http://10.180.158.23:8000/widget/demo。正式网站使用 HTTPS 反向代理，联调页不要公开给客户。之后统一使用 enterprise.sh，旧 docker-host.sh 仍是 SQLite 兼容部署入口，不要混用两份 Compose 启动同一个服务。

## 更新知识与图片

固定使用 knowledge_sources/SmartTITU客户问答.docx，内容覆盖更新，避免同一份文档以不同文件名重复入库。文件改名不会自动替换旧文档ID；先 documents 核对，显式 deactivate 无需的旧ID，再入库。不会自动停用“缺失文件”以免误删资料。

```bash
sh scripts/enterprise.sh exec assistant python manage.py documents
# 需要时显式停用旧文档：python manage.py deactivate DOC-实际ID
sh scripts/enterprise.sh exec assistant python manage.py ingest &&
sh scripts/enterprise.sh restart assistant &&
sh scripts/enterprise.sh doctor
```

普通更新无需 --rebuild；更换 Embedding、模型版本或切分配置才全量重建。纯正文版本更新会自动按活动修订检索，重启用于同时刷新媒体登记和前端资源。新增配图同时更新已登记媒体文件、data/media.json 和 Word 的配图ID，不读取 Word 内任意图片作为可公开资源。扫描PDF需要先 OCR，本版不自动识别扫描页。

## 评测与发布验收

所有私有问法与报告写入 evaluation/private/ 或 var/，禁止上传公开仓库。为每个已入库主题生成 5 个待审阅问法：

```bash
sh scripts/enterprise.sh exec assistant python manage.py prepare-evaluation \
  --variants 5 --output evaluation/private/questions-draft.jsonl
```

当前50主题预计250条，但不是“自动生成即正确”。先审阅每条 query、expected_ids、expected_images；补充短事实/数字到 required_terms、禁止串入的内容到 forbidden_terms，加入真实用户问法、口语、错字、多轮及知识外负例。确认后逐条设 reviewed=true。required_terms 可填字符串，或同义词数组表示任选一个。负例 expected_ids=[]。实际模型生成的数据需要独立人工复核，不作为无偏质量证明。

```bash
sh scripts/enterprise.sh exec assistant python manage.py evaluate \
  --dataset evaluation/private/questions-reviewed.jsonl \
  --output evaluation/private/retrieval-report.jsonl
sh scripts/enterprise.sh exec assistant python manage.py evaluate \
  --dataset evaluation/private/questions-reviewed.jsonl --answers \
  --output evaluation/private/answer-report.jsonl
```

报告分别统计 dense_recall_at_k、fused_recall_at_k、selected_recall、负例拒答、知识覆盖、引用、关键事实、配图及 p50/p95 耗时；失败退出码为1。expected_ids 是版本关联的片段ID，更新 Word 后发现过期会明确报错，必须更新标注。默认不测大模型回答，--answers 才走完整客服流程；测试会话使用独立评测身份并在每条结束后删除，不混入客户历史。完整答案检查需 ANSWER_MODE=llm。自动关键事实检查不是语义判断的替代品，最终仍要抽查事实、完整性、友好程度。多轮上下文另外用真实会话验收。

发布前至少验证：全部主题都有多个自然问法；相关回答引用正确、图片不串题；知识外问题引导人工；连续追问及更换主题；账号A无法读取B的历史；服务重启后历史保留。测试集上的全通过只说明该测试集通过，不承诺任意问法100%。

## 备份、恢复与回退

```bash
sh scripts/enterprise.sh backup
```

备份包含 PostgreSQL 中的聊天、知识、原始修订、向量副本和 LangGraph 检查点。Milvus 可以由 PostgreSQL 中的活动向量重建，不需要重新调用模型。同步保管 .env、来源 Word 与媒体文件，模型权重按你自己的备份策略保管。命名卷不是备份，不要执行 docker compose down -v 或 prune volumes。

恢复时先启动基础设施，在**空的同配置 PostgreSQL 数据库**内执行；脚本不会删除已有库。可在单独恢复主机或经管理员准备的空库演练。恢复命令遇到目标已有表会停止，不要通过 --clean 擅自覆盖在线数据。

```bash
sh scripts/enterprise.sh restore backups/实际备份.dump &&
sh scripts/enterprise.sh start &&
sh scripts/enterprise.sh doctor
```

若需要回到 SQLite：先暂停流量并等待在途请求结束，停止客服后导出**当前** PostgreSQL，保留上线以来新增会话，而不是直接拿迁移前旧库覆盖：

```bash
sh scripts/enterprise.sh export-sqlite backups/sqlite-rollback-日期
```

输出目录包含 assistant.db、rag.sqlite3、export.json。核对数量和文件后，在本机 .env 设置 DATABASE_URL=''、VECTOR_BACKEND=sqlite、APP_WORKERS=1。保存原 var/ 文件，不覆盖；可将新导出的两个文件复制到 var/rollback-assistant.db 和 var/rollback-rag.sqlite3。同步修改 compose.enterprise.yaml 的 assistant.environment 中 DATABASE_PATH、RAG_INDEX_PATH 为这两个容器绝对路径，再执行 enterprise.sh start。新版镜像可运行兼容模式，不必退回缺依赖的旧镜像。此次回退保留已完成历史和知识版本；不迁移数据库之间的在途检查点。PostgreSQL和Milvus卷留存，禁止删库。回退完成后如果 SQLite 又产生新消息，不能把旧迁移脚本当双向同步工具直接切回 PostgreSQL，应另做维护迁移核对。

## 接入企业网站

iframe、自带浮窗、直接API都保留，调用同一套服务和会话。示例见《悬浮弹窗接入》《API对接说明》。三种方式统一使用平台后端签发的企业/用户短期凭证；当前仓库无法代替你的真实登录平台完成此接口。

业务后端验证当前已登录用户，从可信服务端会话取得 tenant_id / user_id，再用 issue_token 签发短期凭证。浏览器不能提交任意企业ID来换取凭证，也不能拿到 AUTH_SECRET。iframe 通过受校验的 postMessage 传递凭证，token 不放 URL；浮窗通过同源 tokenEndpoint 获取；直接API使用 Authorization: Bearer。FRAME_ORIGINS/CORS_ORIGINS 填精确业务来源。平台的登录、登出、角色权限与凭证更新须联调验收后才对外开放。

## 运维与扩展边界

APP_WORKERS 默认1，PostgreSQL模式可设2至4，通过共享关系库的咨询锁和幂等约束防止跨进程重复回答。每worker独立模型连接池、关系库池及指标，不能把4个worker等同于4倍模型吞吐；先测模型并发，再扩容。Compose关系库最大连接数300，需结合其他应用和内存调整；外接库也须满足连接预算。

/health 为存活；/ready 检查活动知识、关系库与当前 Milvus 集合，故障返回503；doctor --models 主动验证上游协议；它们都不能代替问答质量测试。/metrics 用 X-Operations-Token 保护，只输出计数和耗时，不包含问题正文；指标是当前worker进程级，重启归零。按需接入你的集中监控和告警系统。

```bash
sh scripts/enterprise.sh exec assistant python manage.py prune-checkpoints --days 30
```

保留聊天消息，仅清理旧工作流检查点。定期执行备份和恢复演练。真实业务查询可在 ToolRegistry 注册只读适配器，权限上下文来自后端身份；余额、订单、工单未接入时明确提示人工，不返回虚构数据。写入工具目前禁止注册，后续必须接入确认、审计和幂等机制再启用。
