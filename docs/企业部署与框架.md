# 企业客服框架

正式升级路径见 [企业升级与迁移](企业升级与迁移.md)。本版使用 FastAPI + Uvicorn、LangChain、LangGraph、PostgreSQL 和 Milvus，保留 SQLite 兼容部署。数据规模、并发承载和模型正确率需要用目标主机的真实负载验证。

## 分层与一次问答

企业平台登录态 → 可信后端签发短期凭证 → iframe / 自带浮窗 / 直接API → FastAPI校验签名、租户用户、来源、字段和大小 → PostgreSQL查询会话、取得跨实例会话锁 → LangGraph检查点 → 意图分流 → 知识检索或已接入的业务工具 → LangChain模型调用 → 引用和配图校验 → 事务保存消息 → JSON或SSE响应。

LangGraph节点为 route、retrieve、generate、business、validate。问候等会话意图直接进入模型生成友好回复，不检索知识；未配置模型时使用友好固定话术。知识问题检索有效资料后才调用模型，证据不足或模型声明无法回答时先推荐相关/常用问题，点击“以上都不是，转人工”后才显示联系方式；二维码未配置就不显示。显式敏感话题经过本地规则跳过检索/生成，其余问题仍受模型范围提示约束；这不是对任意敏感表述的完整审核保证。模型不得任意调用业务写操作；实时余额/订单未接入时明确告知。人工联系方式引导不代表已经创建人工接待会话。

LangChain包含实际模型初始化、提示构建、BaseRetriever和Runnable调用链。LangGraph保存每次请求的节点状态，异常中断可用相同request_id继续。相同request_id不得换问题；完成后的重试直接返回已保存响应，不重复调用模型或写消息。检查点线程按租户、用户、会话和请求ID生成。跨数据库迁移不搬运未完成检查点，需维护窗口排空请求。

## 知识入库

Word / 文本PDF / Markdown / TXT → 按标题或页解析 → 提取正文、原文URL、图片登记ID和出处 → 分块（当前1000字符、100重叠；短问答整体保留） → 去掉用于展示的URL等检索噪声 → BGE-M3生成1024维向量 → 归一化 → 保存文档修订与向量。

PostgreSQL保存会话、消息、文档路径、活动版本、原文件快照、片段、向量备份及工作流检查点；Milvus用HNSW/COSINE索引做向量候选检索，不存私有正文。新向量先写入，再原子发布关系库活动修订；查询只允许活动文档/修订，避免旧版或未发布向量混入。失败保留旧活动版本。新版本不会删除旧引用对应的原文。SQLite模式继续本地向量扫描，只用于兼容与回退。

## 匹配与阈值

当前问题生成向量 → Milvus语义候选 + BM25候选 → RRF融合 → Qwen3 Reranker排序 → 最多3个资料片段作为LLM证据。默认每路top12，融合最多24；向量候选起始余弦门槛0.45。BM25覆盖及标题主题保护可补救语义候选漏召回，但不直接返回写死FAQ答案。完整主题请求优先该主题，普通自然问法仍通过语义召回。相似度0.45不是45%正确率；重排默认门槛0只是排序，不是已经校准的“匹配概率”。

图文由本轮实际引用的记录绑定，最终最多4张，历史图片不能决定本轮图片。模型引用ID、图片ID必须属于当前允许集合；不能用任意模型生成URL代替登记配图。无有效候选则不调用模型补写知识，先推荐问题，用户选择后再展示人工联系方式；有候选也仍可能因为证据不足拒答。阈值、topK、重排门槛需依据私有多样问法评测校准，不承诺任意问题100%正确。

## 会话、流式和并发

聊天历史按企业和用户隔离，默认传最近12条消息；空闲超时后历史仍保存，但新回答不携带旧上下文。短指代追问会参考前一个用户问题改写检索，独立的新问题不叠加旧主题。本版没有跨会话长期用户画像。

JSON接口保持兼容；SSE接口先输出进度、心跳，在答案通过引用和配图校验后发送delta及完整结果，不把模型原始JSON、思考内容直接推给客户。因此首段答案仍需等待模型完成校验。前端180秒超时，Embedding/重排默认各30秒，LLM45秒且不自动重试；客户断开后在阶段边界取消，已在途的同步模型调用等待自身超时结束。

Uvicorn默认1worker，PostgreSQL模式允许最多4；每worker最多32个应用请求，超出503，用户限流429，同会话并发409。模型客户端复用连接池；关系库按线程借连接，不共享事务连接。PostgreSQL咨询锁支持多实例，同一会话只允许一个请求处理，幂等唯一约束防止重复消息。数据库、GPU模型或外部接口拥堵仍会限制吞吐。

## 扩展范围

已提供可插入的只读业务工具注册、租户权限上下文和结果约束。真实业务接口、写入审批、人工工作台、企业私有知识分区、多机高可用、集中审计/告警属于后续集成，当前不会伪装已完成。现有知识仅面向已认证客户共享的外部资料，不应放内部或某企业专属资料。

固定单机Compose提供PostgreSQL、etcd、MinIO、Milvus与客服服务，正式公网需HTTPS代理、真实SSO联调、备份与恢复演练和负载验收。Docker可启动并不等于上述集成和问答质量已经达标。
