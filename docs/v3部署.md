# v3 匿名访客入口

用户打开网页即可使用客服，不再填写用户ID。后台给浏览器自动分配随机匿名身份，通过HttpOnly签名Cookie保存30天，每次访问页面或刷新凭证时续期。访问凭证仍为1小时有效，在页面内存中自动刷新；浏览器不保存访问凭证到localStorage。匿名Cookie不能作为API凭证使用。

聊天消息仍在服务器数据库保留最近7天。同一站点、同一浏览器再次访问可查看其历史；新建会话有独立上下文。换浏览器、换电脑、无痕模式、清除Cookie、浏览器限制存储或改变站点域名，可能成为新访客。多人共用同一浏览器可看到同一访客历史；这不是账号身份识别。固定用户ID入口已移除，旧手填ID历史仍按原身份保存，不自动合并或归给匿名访客。

正式嵌入iframe仍通过现有平台凭证协议验证用户，匿名改动不接受浏览器自报平台账号。

## 同机部署

```sh
cd ~/ai_customer
git clone --branch v3 --single-branch https://github.com/lsy199904/AI-customer-service.git ai_customer_v3
cd ai_customer_v3
cp ../ai_customer_v2/.env .env
chmod 600 .env
sh scripts/v3.sh build
sh scripts/v3.sh start
sh scripts/v3.sh doctor
```

默认 `http://服务器IP:8200/widget/demo`。直接访问 `/chatbot` 进入同一页面。无需手动领取凭证。现有部署更新后执行 `docker compose -f compose.v3.yaml restart assistant` 加载新代码；无需重新入库或构建镜像。执行Compose前需设置ASSISTANT_UID、ASSISTANT_GID，或由部署脚本启动。

`compose.v3.yaml` 只启动客服，项目名ai_customer_v3，镜像ai_customer-assistant:v3，默认8200（V3_PORT可覆盖），默认监听0.0.0.0。继承.env中的PG、Milvus和模型服务连接，复用现有数据库与知识索引，日志写在v3自身var/logs。不要复制v2的var目录或执行数据迁移。

访问凭证仍使用当前AUTH_SECRET签名，保留密钥以延续匿名Cookie。HTTPS下Cookie启用Secure；如经反向代理提供HTTPS，请确保正确传递并信任代理协议头。新Cookie名称与旧v2入口不同，避免同主机不同端口访问时相互覆盖。有效的旧匿名身份可迁移至新Cookie；旧手填ID不会迁移。
