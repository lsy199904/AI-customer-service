# v3 固定测试用户入口

v3 是受控测试版：输入固定用户ID，不验证账号密码。同一ID可读取同一历史，因此只向可信测试者开放。正式iframe接入仍使用平台后端签发身份；不接受浏览器自报平台账号。固定ID区分大小写，不可冒用平台身份，使用独立 `fixed-v3:` 用户命名空间。

## 同机部署（保留 v2）

在独立目录clone，不要在v2目录切换分支：

```sh
cd ~/ai_customer
git clone --branch v3 --single-branch https://github.com/lsy199904/AI-customer-service.git ai_customer_v3
cd ai_customer_v3
cp ../ai_customer_v2/.env .env
chmod 600 .env
sh scripts/v3.sh build
sh scripts/v3.sh start
sh scripts/v3.sh doctor
```

默认 `http://服务器IP:8200/widget/demo`。直接打开 `/chatbot` 也进入测试页面；嵌入的iframe仍走平台凭证协议。首次输入例如 `test001`，浏览器记住ID（不存凭证），可点击左下角“切换用户”。无本地存储权限时，每次重新输入相同ID即可。凭证1小时有效，后台按固定ID重新签发。最近7天消息可见，不是登录后重新延长7天。历史需要点击客服右上角历史按钮查看。

`compose.v3.yaml` 只启动客服，固定Compose项目名ai_customer_v3、独立镜像ai_customer-assistant:v3，默认8200（可用V3_PORT覆盖），不会启动新的PG、etcd、MinIO或Milvus，也不会占用v2端口。继承.env的PG/Milvus/模型连接设置，复用现有数据库和知识索引；不是数据库完全独立副本。新测试用户与v2随机用户分开，旧会话不自动合并。默认监听0.0.0.0，需在服务器防火墙/代理允许8200并限制可信测试者访问。

日志写入v3自身var/logs；如需完整处理内容，沿用.env中的LOG_DEBUG_CONTENT设置。PG仍是同一个数据库；两个版本的清理任务均按现有7天规则运行。不要复制v2的var目录或执行迁移/重新入库。若.env中配置了本机相对证书文件，请同步该文件；不要公开.env。

更新：git pull --ff-only origin v3，然后重新执行build和start。start会等待健康；失败执行 `sh scripts/v3.sh logs` 查看。
