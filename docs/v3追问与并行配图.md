# v3 追问解析与并行配图

## 流程

本轮问题 → 识别独立新问题/依赖前文的追问/歧义 → 补全检索问题 → 原有混合召回与重排 → 并行启动正文生成和配图预判 → 实时文字delta → 来源metadata → 配图快速校验/去重 → 完成帧并保存。

追问解析位于 `app/query_context.py`。只有存在历史、且问题可能依赖上下文时才调用已配置模型；明确的“支付流程是什么”等新问题直接检索。带连接词的新话题仍可被语义解析判为独立问题，不强行继承旧主题。追问改变日期、金额或主体时，以本轮条件为准；不包含历史助手的答案正文，不修改知识文档。不能确定指代时先澄清。结构化改写无效时使用保守的用户问题上下文回退；改写、Embedding和重排共用既有检索超时预算。

知识回答模型仍使用当前有效证据，`resolved_question` 只用于明确主题和本轮条件，不作为业务事实。20轮上下文、7天保留、认证和会话隔离均不改变。

## 配图与流式响应

`app/workflow.py` 在正文生成前启动有界后台配图任务，配图和正文共用解析后的主题。预判不再读取尚未生成的答案，也不再据此决定引用。正文结束后按句/分句核对实际支持的知识，并利用这些来源过滤图片；不会从全部召回知识中自动汇总图片。

SSE新增可选 `metadata` 帧（`citations`、`images`、`media_pending`），原有 `status`、`delta`、`complete` 保持。自带浮窗已支持来源先展示、配图等待提示。直接API调用者可选择消费metadata；不处理此帧也可继续使用complete。

默认正文后最多再等0.35秒配图，可选 `MEDIA_FINAL_WAIT_SECONDS`，上限2秒。超时或容量不足时不附图，不阻塞回答，晚到结果不更新消息或历史。后台推理可能继续至传输超时，但后台任务最多4个且不使用无界排队。完成时选中图片作为消息的一部分保存，历史读取不重新计算。

## 验证与部署

使用Python 3.12及锁定依赖，276项测试中268项通过、8项因真实PostgreSQL/私有文档环境未配置而跳过。新增测试覆盖：任意日期改变、金额与主体变化、新支付话题、歧义澄清、重新检索、正文持续流式、并行任务启动屏障、来源先于配图到达、慢图等待上限及晚到结果不回写历史。Node流解析测试覆盖metadata帧。语义模型用受控输出测试，未连接生产Qwen做问法质量评测；未在服务器实际启动Docker。
