# 会话、企业限流与检索超时

本次策略配置以README“会话、限流与检索策略”一节为准。

| 设置 | 默认值 | 口径 |
| --- | --- | --- |
| SEMANTIC_MIN_SIMILARITY | 0.75 | 向量余弦候选门槛；BM25可补召回 |
| SESSION_RETENTION_DAYS | 7 | 每条消息保存7天；最后活动超过7天的会话清理 |
| SESSION_CONTEXT_ROUNDS | 20 | 最近40条消息进入模型；不强制结束聊天 |
| TENANT_MESSAGES_PER_MINUTE | 20 | 全企业用户和会话共享滚动60秒额度 |
| RETRIEVAL_TIMEOUT_SECONDS | 15 | 元数据、向量生成、召回、融合、重排共享预算 |
| SESSION_IDLE_SECONDS | 1800 | 空闲后开启新的上下文片段，仍保留期限内历史 |
| SESSION_CLEANUP_INTERVAL_SECONDS | 300 | 启动立即清理，之后周期分批清理 |

API bootstrap包含 `policies`；`manage.py check` 输出配置策略。认证企业标识来自可信登录凭证，不接受请求体伪造企业标识。限流在PostgreSQL中事务锁定企业额度记录，跨进程共享；SQLite仅用于兼容部署。

清理跳过正在处理请求的会话，PostgreSQL多进程通过维护锁与会话锁协调。完成后的消息仍保存至7天期限；对应冗余检查点即时删除。取消未完成请求保留可恢复检查点，随会话/过期消息清理，避免检查点绕过历史保留政策。备份单独管理。

应用检索超时后返回reason=retrieval_timeout、可重试提示及推荐问题；仍可按用户选择转人工。不会继续生成，也不显示底层异常或密钥。检索繁忙会返回暂时不可用提示。网络、数据库和向量RPC单阶段超时均限制在剩余预算内；16个检索执行槽位防止超时后台任务无限排队，运行中的同步调用受自身超时约束。

修改策略不改变Embedding模型及切分指纹，不需要重新入库。部署需重建应用容器以加载env_file；单纯restart不能加载修改后的环境变量。首次启用7天政策会清理在线库中已过期历史，建议部署前按现有运维方案备份。
