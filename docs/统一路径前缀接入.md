# /smart-bot 统一接入前缀

本次基于 v3-anonymous-iframe 分支，统一第一方浏览器请求路径。模型服务及业务方自行提供的登录接口不属于此路径空间，不改写其地址。

```html
<script src="http://10.180.158.23:8200/smart-bot/iframe-anonymous.js"></script>
```

- iframe：`/smart-bot/chatbot/anonymous`
- 匿名认证：`POST /smart-bot/widget/anonymous-auth`
- 初始化、会话、问答及 SSE：`/smart-bot/v1/...`
- 静态 JS/CSS：`/smart-bot/widget/...`、`/smart-bot/widget.js`
- 图片：`/smart-bot/media/...`
- 健康检查：`/smart-bot/health`、`/smart-bot/ready`

路径前缀不属于 postMessage 的 origin，通信校验仍使用协议、主机和端口。匿名 Cookie 的 Path 同步调整。返回数据中的内部图片和来源链接同步带前缀；历史数据中保存的旧图片路径在展示时转换，无需重新入库或迁移会话。

## 网关转发

网关保留 `/smart-bot` 转发给客服服务。Nginx 示例（proxy_pass 后不加斜杠）：

```nginx
location /smart-bot/ {
    proxy_pass http://10.180.158.23:8200;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 240s;
}
```

若网关已有全局鉴权，须按公开匿名客服的产品范围允许认证接口及必要静态资源访问。平台 HTTPS 页面必须加载 HTTPS 脚本。跨域嵌入仍需配置 FRAME_ORIGINS；同域网关不需要给 postMessage origin 加路径。

为了兼容原有容器健康检查与运维脚本，后端暂时保留旧根路径入口；新版页面所有客服资源和 API 请求均走新前缀。旧入口不是另一套会话服务。网关只需暴露 `/smart-bot/`。

## 更新

在当前运行匿名入口的仓库执行：

```sh
git pull --ff-only origin v3-anonymous-iframe
sh scripts/v3.sh start
```

无需重新入库。启动脚本会重新创建服务以重新加载挂载的代码。宿主平台需同时更新脚本地址并刷新页面。

新 Cookie 路径与旧路径不同，已有匿名浏览器首次切到新版可能生成新访客身份；既有数据不删除，不自动合并身份。之后同一有效 Cookie 下继续复用历史，浏览器 Cookie 限制仍适用。
