# v3 策略统一与回归

本次是策略维护重构，不改变知识库业务内容、向量文本版本、混合召回、重排阈值、最多三条辅助知识、身份认证或会话隔离。

## 一份业务流程配置

`data/business_flows.json` 集中定义十类流程的标题、别名、六类已支持的分步引导阶段、后续流程、推荐顺序，以及图片的流程归属和优先级。阶段仅引用当前知识的步骤编号，不写入业务答案。

`app/business_flows.py` 启动时校验并加载配置。分步引导、推荐问题、图片判断共用此配置。新增未定义引导阶段的流程不会自动开放分步办理。

`data/media.json` 继续管理图片 ID、地址、说明等资源信息；Word 继续以既有图片 ID 绑定知识章节。原有流程图片归属已迁入流程配置，由 MediaCatalog 加载时补齐，图片 ID 和地址均未更改。旧登记中的流程字段仍可读取；中心配置已定义的图片以中心配置为准。

## 一个配图决策入口

`app/image_policy.py` 的 ImagePolicy 为语义模型与保守离线策略提供统一的决策校验和最终选择入口。语义模式理解本轮问法、必要上下文与候选资料；摘录模式及无独立规划接口的旧适配器使用保守策略。语义模型调用失败不再尝试另一套关键词配图，而是不附图。

视觉模型只决定需要图片与否、主流程及候选图片，不再负责选择文字引用。文字来源仍按实际支持正文的知识核对。最终选图统一执行来源支持、主流程约束、专属流程图优先和 ID/资源地址去重。

并行执行、任务容量、短等待、正文增量和来源提前发送机制保持不变。慢图片不会阻塞整段正文；历史直接读取已保存结果，不重新选图。

## 通用标题策略

`app/title_policy.py` 集中维护明确标题、操作流程标题、有界操作与产品简称、弱相关前缀的优先级。只允许完整操作词加产品标识省略通用角色名，例如“安装 MetalLB”对应“安装 MetalLB 负载均衡器”。不添加按产品名称硬编码的分支；“安装”不会提升“配置”或“故障排查”为明确匹配，多个等价标题仍交由检索层处理歧义。

标题正规化、检索文本和融合排序算法不变，不需重做 Embedding。

## 回归与部署

新增 `tests/test_policy_registry.py` 校验配置迁移、统一决策、模式兼容、非法 ID、规则咨询不配图、通用标题简称与边界。

沿用原有全部测试，覆盖 MetalLB 专题保护、正文实时流式、后台依据告警不替换回答、模型异常、无知识命中、追问与换话题、配图去重、慢图片、历史一致性及权限隔离。自动化使用受控模型响应，不能代替部署后真实模型问法验收。
