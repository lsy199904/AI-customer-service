# 知识文档管理

本期采用固定源目录加显式发布。运营人员维护 Word，服务端管理人员执行一次入库命令即可更新。后续若要让运营独立操作，可在现有管理功能上增加带管理员认证的上传、预览、发布页面；当前没有浏览器上传入口。

## 文档放哪里

`knowledge_sources/` 是正式语义问答的来源目录，支持子目录。首份清洗版 Word 包含71个问答，按问题分节，已经保留原 PDF 出处。默认不导入旧134条 JSONL，避免把术语释义当成售后故障答案。

一个文件负责一个主题，例如账号、模型接入、费用、故障。一期先用一份 Word 也可以，规模增加后再按主题拆分。同一业务口径只维护一个有效版本，避免新旧政策相互矛盾。

## Word 怎么写

使用 `.docx`，旧 `.doc` 请另存。用 Word“标题”样式写文档名，“标题1”至“标题6”写问题或章节，普通正文写完整操作步骤、适用条件、限制和答案。版本独立写成 `版本：2026-10-22 v1`。每节末尾可以写 `来源：原始文件及页码`，系统保存为引用信息。

包含章节标题的 Word，文档标题与第一节之前的说明只作为导言，不入检索正文。因此会影响回答的适用条件必须写在对应章节正文里。不要只放在封面或页眉。表格会转换为带列名的文字；多级合并表格和复杂版式建议先改写成普通段落。不要仅在图片内放关键知识。

PDF 支持可提取文字的文件，保存物理页码；扫描件不自动 OCR，文字不足会拒绝入库。页眉页脚、复杂多栏内容可能影响文字顺序，优先使用已清洗 Word。文本采用 UTF-8。单文件上限25MB，Word解压上限60MB。

## 更新规则

|操作|做法|结果|
|---|---|---|
|新增|放入新文件后运行 `python manage.py ingest`|新增文档和片段|
|修订|覆盖相同路径的文件后运行入库|创建新修订，替换当前检索内容|
|重复运行|直接再次入库|相同文件不调用Embedding；相同文本片段复用向量|
|下架|`python manage.py deactivate 文档ID`|新回答不使用；历史引用保留|
|恢复|`python manage.py activate 文档ID --revision 完整修订哈希`|切换到指定旧修订|
|改名或移动|新路径入库后停用旧文档|路径作为文档身份，不能自动识别为重命名|
|误删源文件|补回文件，或显式停用|不会自动移除已有知识|

`python manage.py documents` 查看文档ID、路径、当前修订、active状态；`python manage.py revisions 文档ID` 查看各次修订。这里的修订哈希由文件内容和处理配置共同确定，与 Word 中的人工版本号分开管理。

停用文档即使文件还在目录中，后续入库也会跳过；恢复后再入库才能发布新的磁盘内容。恢复旧版本只切换数据库，不改源文件，因此要长期保持旧版本时需同时恢复对应源文件。不同向量模型版本的修订不能直接混用，需恢复源文档并重建。

整批文件解析和Embedding都成功后才发布新版本。出错时旧版本继续可用；修复错误再重试，成功生成的向量可复用。并行发布冲突会报错要求重试，不覆盖另一个操作。不要同时由多人编辑同一份源文件并发布。

原文和各修订被保存在知识库数据库中，历史回答能下载当时版本。停用不是彻底销毁：如需彻底删除敏感资料，还需清理历史、原文快照及备份，本期没有自动销毁命令。

## 何时重建

新增和修改文档用普通 `ingest`。Embedding模型/权重/端点/处理版本或切分配置变化时用 `ingest --rebuild`；同名模型权重变化需要人工更新 `EMBEDDING_REVISION`。重建会重新处理所有活动文档，缺失活动源文件时会中止，先补回或停用。只改 Reranker 或聊天模型一般不需要重做文档向量。

## 简单验收

每次更新后验证三类问题：新增内容能否回答、同义表述能否找到、无相关知识是否引导人工。使用真实客服问题调召回门槛，不把余弦或重排分数直接理解成正确率。模型能够拒答也不代表所有错误知识都会被拦住，内容仍需人工审核。

目录中的全部活动知识是所有已认证客户共享的客户资料。不要加入内部销售话术、个人资料、模型密钥、合同或企业专有内容。本期没有知识按企业隔离。

## 备份

`python manage.py backup` 同时备份会话库、知识库；源目录也要备份。日常不要手工编辑 SQLite 内的向量或记录，也不用手工维护 JSONL。历史修订和原文件快照会持续增长，可定期检查磁盘占用；本期未实现自动保留期清理。

## 给章节绑定回复图片

在正文后独立写一段 `配图：enterprise-register`，对应图片先放到app/static/media并在data/media.json登记。不要把“配图”行写在标题里，也不要只把截图嵌入Word而没有登记和标记。入库会把图片ID作为元数据保存，不把它当作问答正文。

成功回答实际引用该章节时固定附图；单纯检索到但没有引用的章节不会自动配图。当前注册认证流程、产品单页、Logo、PPT和PDF架构图及Hub操作截图已登记30张图片，按实际引用章节配图。图片更换和文档修订的具体操作见 [图片回复与人工联系](图片回复与人工联系.md)。

当前71问引用的30张配图及 `data/media.json` 已随Git更新，服务器只需拉取。Word与原始PDF仍不随本次发布上传。
