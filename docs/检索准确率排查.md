# 检索准确率排查与本次修复

本次针对两个实际错例：企业注册与认证流程被拒答，以及TITUHub概况引用了核心能力章节。错例说明最终结果不符合文档预期，但截图无法直接证明Embedding或Reranker本身错误，真实服务仍需检查候选与排序。

## 修改内容

1. 向量化与重排只使用去编号的章节标题和正文；原文链接、图片URL及来源说明不再进入检索文本。完整正文、可点击来源和配图ID仍保留在原记录中，Word无需修改。
2. 向量召回与BM25并行生成候选，用RRF融合。语义候选不要求关键词相同；词法候选需有足够覆盖，避免公共词捞入无关内容。
3. 完整章节标题匹配可补回低于向量门槛的正确章节；匹配会统一大小写、产品名空格、问题/页码编号及常见问句外壳。标题不是必选门槛，也不是两条硬编码答案。
4. 明确问完整章节时，优先用该章节作为证据，避免概况被几个功能章节代替。标题不同的普通提问继续按混合召回与重排选证据。原RERANK_MIN_SCORE仍被尊重；不把重排分数当准确率。
5. 模型提示词优先完整章节证据，禁止在客户回答正文输出KB-/DOC-编号；模型输出及旧历史展示均做编号清理。来源按钮保留但不展示问题序号。

## 本次升级步骤

检索文本处理版本改变，必须重建一次向量。没有新增Python依赖，不必重新构建已完成FastAPI升级的镜像：

```bash
cd ~/ai_customer
git pull --ff-only origin main
sh scripts/docker-host.sh exec assistant python manage.py ingest --rebuild &&
sh scripts/docker-host.sh restart assistant &&
sh scripts/docker-host.sh exec assistant python manage.py check
```

只保留一个活动Word时应为71条。已停用的长文件名重复记录仍保持停用，不会因重建自动恢复。旧来源快照与历史会话保留。

## 用真实模型做诊断

下面命令调用已有Embedding和Reranker，不调用聊天模型、不打印密钥；仅输出问题、标题、ID、分数与配图绑定。只在可信服务器终端运行，不新增公开调试接口。

```bash
sh scripts/docker-host.sh exec assistant python manage.py retrieve --query '企业注册与认证流程是什么'
sh scripts/docker-host.sh exec assistant python manage.py retrieve --query 'TITUHub概况'
```

查看selected与diagnostics：

- 注册问题应选中企业注册与认证流程章节，并带enterprise-register图片ID。
- Hub概况应选中问题10的概况或同主题概况章节，不应被资源管理运营、模型内路由等核心能力章节替代。
- dense_top为纯向量排名；candidates显示BM25/RRF与完整标题信号；reranked显示重排分数及最终是否选中。
- 若正确条目未在候选中，排查入库内容、向量服务与问法；候选正确但重排错误，检查Reranker服务的模板、相关/无关对照及阈值；selected正确而回答偏离，再检查聊天模型输出。
- 可在retrieve后增加--no-rerank比较取消重排时的选择结果，无需修改.env或生产服务配置。

完成入库后在新会话测试，避免旧回答或旧来源造成误判。自动回归使用故意不利的向量与重排替身来验证这两个失败模式，并不代表已测得目标服务器真实模型准确率。


### 单一流程问题和配图隔离

“安全审计流程”等明确的流程请求，会优先选择“安全审计”章节；“快速使用流程”可对应“快速使用检查清单总结”。完整标题优先于扩展标题，只有“流程”等泛词不会限定章节。对比或多主题问题继续使用多段证据。

普通知识问答仅提供本轮章节绑定的配图，最终展示限于本轮实际引用的章节。明确索要图片时才允许使用当前问题的图片关键词查询。切换问题后不会自动继承历史配图；已显示的历史消息仍保留原图。快速使用清单当前没有绑定配图，应只返回说明及来源，不应重复注册或审计图片。

本次仅调整候选筛选和回答约束，不改变向量内容或索引版本。拉取后重启服务即可，无需重新上传Word或全量重建。新建会话测试“安全审计流程”→“快速使用流程”，必要时用 `manage.py retrieve --query` 检查本轮所选章节。
