# 图片回复与人工联系

## 人工联系

企业微信二维码未提供时，`SUPPORT_QR_URL` 保持空白，人工联系卡片只显示已配置的电话、邮箱。未命中先展示推荐问题和“以上都不是，转人工”入口；用户选择后再展示联系方式。

## 图片关联与展示是两件事

Word 的 `配图：图片ID` 只登记本节可用图片，不表示回答引用该节就必须附图。多个条目可以关联同一图片，入库后的知识 `image_ids` 保留这些关联。

运行时先生成答案并选择支持答案的来源，再独立判断本轮是否需要图片及主要业务流程。LLM 模式使用相同已配置模型做一次非流式、结构化的语义判断；输入包括本轮问题、最近用户问题、答案、当前知识和登记图片，不以固定关键词或重排第一名决定配图。判断 JSON 不发送给客户。无候选图片时不增加这次调用。

- 事实、额度、时间、生效条件、默认星级和局部追问默认只答文字。
- 完整办理流程、明确看图或需要视觉解释时才选图。
- 背景流程不等于主要流程，例如“注册完成后怎么订购”主要选订购。
- 只有明确询问多个流程，才允许选多个流程图。无法明确对应时不配图。
- 同一流程优先选专用流程图，按图片ID和实际资源URL去重，最多4张。
- 图片必须属于本轮实际支持答案的知识；没有知识正文的明确看图请求，可使用本轮登记图片候选。模型不能编造资源或ID。
- 模型判断异常/格式不合法时保留文字和原有来源，不自动附图。extractive 模式采用保守的本地规则。

正文保持现有输出方式；图片选择在最终组装时完成，放在答案底部。最终 `images` 与来源一起保存到消息，读取历史不重新选择。修复前已保存的旧消息不作追溯改写。

## 登记流程图片

1. 将获准对外展示的 PNG/JPEG/WebP/GIF 放入 `app/static/media/`。
2. 在 `data/media.json` 登记，例如：

```json
{
  "id": "business-subscription",
  "title": "服务订购流程",
  "alt": "服务订购流程图",
  "url": "/media/business-subscription.png",
  "keywords": [],
  "knowledge_ids": [],
  "flow_ids": ["subscription"],
  "flow_priority": 100
}
```

现有流程ID：`register`、`login`、`verification`、`contract`、`subscription`、`rating`、`delivery`、`recharge`、`payment`、`invoice`。已有10张独立业务流程图使用优先级100；兼容旧合并图使用优先级10。优先级只用于选图，不参与检索或重排。非流程截图、logo等可不配置 `flow_ids`，在明确视觉需求时选择具体登记图片。

3. 对应 Word 节中另起一段：

```text
配图：business-subscription
```

多个ID用逗号分隔。图片ID必须已登记；此元数据不进入Embedding。仅修改登记表的流程归属/优先级无需入库，修改Word关联时才需要正常增量入库。Word内嵌图片仍用于人工阅读，运行时使用已登记资源。

本地 `/media/` 图片公开可访问，只能登记批准对外展示的内容。也支持受控HTTPS图片地址；窗口支持缩略图、点击放大及查看原图。

## 日志和更新

每请求新增 `image_selection_completed`：是否需要图片、理由、主要流程、候选图片、最终图片、未选图片和排除原因。语义判断不可用记录 `image_planning_unavailable`，不会把已成功的文字回答改为失败。

此次 v3 配图改造不改变Word、检索阈值、最多3条知识辅助生成、认证或会话隔离。无新增依赖，不用重新入库。服务器执行：

```sh
cd ~/ai_customer/ai_customer_v3
git pull --ff-only origin v3 &&
sh scripts/v3.sh start &&
sh scripts/v3.sh doctor
```

`start` 会重新创建 assistant 容器，加载新代码和图片元数据；挂载部署不必重新构建镜像。更新后以新消息验证，历史已缓存的旧请求不会重新生成。

## 本次验证

Python 3.12、项目锁定依赖下全量263项测试：255项通过、8项跳过（真实PostgreSQL/私有文档环境未配置）。新增16项配图测试覆盖订购同义问法、注册背景、明确多流程、默认星级/额度/时间、不重复局部追问、明确星级看图、产品介绍、ID/URL去重、语义判断异常、extractive模式、HTTP流式完成帧及历史重载。受控测试同时断言3条检索知识仍送入生成，以及“保留登录来源但不附登录图”。

语义模型输出使用受控替身验证流程和约束；未连接服务器的真实Qwen进行自然问法质量评测，未实际启动服务器Docker。有候选图片时增加一次结构化模型调用，可能增加最终来源/图片就绪时间；不影响已有正文输出通道，无候选图片时不额外调用。
