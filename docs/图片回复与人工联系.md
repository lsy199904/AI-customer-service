# 图片回复与人工联系

## 当前人工卡片

目前没有真实企业微信客服二维码,`.env`中的`SUPPORT_QR_URL`保持空白。无知识命中、模型依据不足、模型错误或用户主动要求人工时,统一返回人工联系卡片,只显示客服电话和邮箱。无二维码占位,不提示扫码,也不会假称人工已经在线接管。

电话和邮箱沿用原资料,正式上线前请由运营确认。未命中先返回推荐问题和“以上都不是，转人工”按钮；用户点击或明确要求人工时，系统才展示联系方式。推荐后的“都不是”等明确拒绝也会展示人工卡片。

## 普通图片怎么返回

回复结构中使用`images`数组。模型只返回已登记的image_ids,服务端映射成可信图片URL,窗口自动展示图片并支持点击放大。当前有用户提供的SmartTITU产品Logo作为图片能力示例,不是客服二维码,不会在人工联系卡片中显示。

增加功能截图或操作示意图:

1. 将PNG/JPEG/WebP/GIF图片放到`app/static/media/`,使用英文文件名,例如`api-key-guide.png`。
2. 在`data/media.json`增加条目:

```json
{
  "id":"api-key-guide",
  "title":"API密钥创建示意图",
  "alt":"在API密钥页面创建密钥的操作示意",
  "url":"/media/api-key-guide.png",
  "keywords":["密钥截图","创建密钥示意图"],
  "knowledge_ids":[]
}
```

3. knowledge_ids可填写真实知识条目ID,使引用该条目时可以选择对应图片;不要填示例虚构ID。
4. 重启服务。用户询问匹配图片时,返回图片卡片。没有所需图片和相关知识时,引导人工,不会临时生成图片。

也可登记由运营控制的HTTPS图片URL。本地图片路由公开可访问,只放已批准对客户展示的图片,不放密钥、后台敏感截图或内部审计材料。窗口会过滤非HTTPS外部地址和非媒体目录路径,不执行HTML。图片加载失败时显示友好提示。

## 以后提供真实客服二维码时

可使用受控HTTPS图片URL配置SUPPORT_QR_URL;也可将图片放到app/static/media并在data/media.json登记,然后配置`SUPPORT_QR_URL=/media/wechat-support.png`。本地图片必须已经登记并存在,否则启动检查拒绝,防止显示无效资源。真实二维码未提供前,保持空白。

普通产品图片与人工联系二维码是两种用途:模型无权决定人工卡片的二维码;二维码只取服务端配置。

## Word章节固定附图

企业注册与认证已更新到客户问答Word v3，共71个知识片段。注册与认证合并为第四问，使用同一张流程图。其他外部章节按来源绑定对应图片。原始HTML保留在 `docs/sources/enterprise-register.html`，回复用PNG为 `app/static/media/enterprise-register.png`。

在对应章节正文之后另起一段：

```text
配图：enterprise-register
```

此行是知识元数据，不会进入Embedding文本或客户答案。多个图片ID用逗号分隔，每个ID必须在data/media.json登记；填网址或未登记ID会使入库失败，旧版本继续保留。长章节切为多个片段时会保留关联。文档更新导致片段ID变化时，无需重绑图片。

通过语义检索找到该章节，且成功答案实际引用了该节时，服务端固定附带对应图片；即使模型没有填写image_ids也会附图。不能仅因该节进入候选列表就强行附图。模型拒答、调用异常、未命中或人工兜底都不自动附流程图。每次最多展示4张图片。已有keywords和knowledge_ids登记仍作为模型可选图片机制保留。

Word中嵌入的流程图用于人工阅读；当前解析器不会自动提取Word里的任意图片。运行时使用登记好的PNG和上述配图标记。

悬浮窗支持点击缩略图预览，并提供“查看原图”链接，在新页面打开高清图片。图片URL来自受控登记，模型不能编造图片网址。本地图片无需登录即可访问，因此只能放已批准公开给客户的资料。

当前Linux整目录挂载部署更新方法：

```bash
cd ~/ai_customer
git pull --ff-only origin main
sh scripts/docker-host.sh exec assistant python manage.py ingest --rebuild
sh scripts/docker-host.sh restart assistant
sh scripts/docker-host.sh exec assistant python manage.py check
```

这次不改依赖，不需要重新构建镜像。更新后刷新业务页面或联调页，获取新版窗口脚本。知识数量应为77；已有其他文档时数量以实际内容为准。用“我们公司第一次使用，怎么入驻？”测试语义问答，若答案引用注册章节应同时附图。真实模型认为证据不足时先推荐问题，由用户选择转人工，不为展示图片强行生成答案。

当前71问引用的30张配图及 `data/media.json` 已随Git更新，服务器只需拉取。Word与原始PDF仍不随本次发布上传。
